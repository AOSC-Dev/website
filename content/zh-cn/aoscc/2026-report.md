## 一、 开场与综述

**主讲人：** 白铭骢

- **年度聚会概况：**
  - 分享议程突破 20 个，涵盖发行版与系统维护、开源硬件、社团运营及 AI 等课题，并首次设立海报展示栏目。
  
- **文化工作进展：**
  - **周边设计**：受人力物力限制，本期周边较去年略少；本年度周边包括通行证、文化衫和星霞 OS 盒装介质。
  - **流浪相机**：流浪相机 2025 圆满结束，手机组出人意料包揽桌面与锁屏壁纸胜出；流浪相机 2026 参与度有所下降，午休期间现场开放报名。
  - **壁纸投稿**：2026H1 壁纸投稿量创新高，收到逾 140 份投稿。
  - **社区期刊**：《安记冰室》已停办，大概率不会恢复。

- **社会工作进展：**
  - **校园行**：去年底三次校园行后，今年陷入停滞（无报名、无线索），但社区仍愿意支持本、专科院校的相关活动需求，亦在探索以地区而非校园为单位的线下活动。
  - **烙饼会**：今年举办了第三届，已成为春节期间的固定栏目（迷你版 AOSCC）。今年首次引入半年期匿名问卷作为问答主干。
  - **开源之夏**：因今年课题完全被限定在 RISC-V 上，且贡献者兴趣不足，自 2020 年该活动开办以来首次未报名。

- **社区组织工作：**
  - **人员规模**：有记录的贡献者突破 150 名。
  - **AI 使用政策**：出台《AI 工具使用及披露约定》，强调社区开发出于研究与实践目的。
  - **基础设施众筹**：
    - 依然“一款难捐”，但由于近期硬件价格上浮，基本暂停了构建机购置。
    - Benderblog、小松和 Revy 等人的捐赠扩充了 x86-64、AArch64、MIPS 和 Power 的服务器算力，特此感谢。

- **技术工作总览：**
  - **安同 OS**：
    - RISC-V 在 Revy 的贡献下维护质量得到提升，无法构建的软件包数量降至 100 以内（占总软件包数量比例 < 5%）。
    - 计划三季度实现 QA 监测网站 (QAshboard)。
    - 增强了对兆芯、海光、龙芯、飞腾、格兰菲等国产硬件平台的支持。
  - **自举项目**：
    - 借助星霞 OS 重启持续推进 Kaboom2，转为仅限交叉编译模式（类似 Buildroot）。
    - 正在通过多种老架构移植不断验证和完善流程。
  - **星霞 OS**：
    - i486 正式版 BuildKit 已于 7 月 26 日发布，正推进桌面软件包构建及性能调优。
    - 当月同步开展 ARMv4、m68k 和 Alpha 移植。
    - 计划推进 PowerPC、loongson2f 和 IA-64 移植。
  - **安可 OS（长毛兔计划）**：
    - 针对非推荐环境下使用者形成的研究性项目，维护 LTS-G 分支（兼容 Linux 6.6/信创）。
  - **维护工具链**：
    - Autobuild4 修正架构定义，新增架构组匹配（FAIL_ARCH）。
    - 针对 32 位架构引入 64-bit time_t 及 libatomic 链接控制。
  - **安装盘与包管理**：
    - mklive 默认采用 EROFS，安装耗时降低近 20%。
    - 取消在线安装镜像 LiveKit。
    - 小熊猫（oma）完成下载逻辑等多项重构并扩展 Termux、帮助本地化等能力。

## 二、 基础设施工作报告

**主讲人：** 网管

- **源服务器迁移与升级：**
  - 2025 年底，旧服务器硬件和网络质量劣化导致服务降级。
  - 2026 年春节前夕，完成众筹并在香港特别行政区上线全新源服务器（新托管商 Nearoute），软件包元数据刷新性能大幅提升。
  - 近期内存与存储大幅涨价，因此内存暂借于北大 LCPU 社区，SSD 有一半为捐赠。

- **Syncproxy 同步架构建设：**
  - **建设原因**：
    - 香港服务器带宽成本高，用户与下游镜像流量持续增长导致主源带宽吃紧。
    - 引入源自 Debian 的 syncproxy 架构，将部分负载分摊给带宽更充裕的下游。
  - **部署进展**：
    - 服务架构正逐步部署，预计 Q3-Q4 完成切换。
    - 计划设置 2~3 个社区自有节点，当前有 uslax 与 cnhkg 两个节点。
  
- **镜像与存储情况：**
  - 过去一年新增 HERNET、ZJU 和 HUST 三个高校镜像源。
  - 软件包存档服务器容量已达 99%。
  - 部分构建服务器存储吃紧但无力扩容。

- **BuildIt 变化：**
  - 配合 i486 移植进入主线，通过 Autobuild 和 ACBS 实现构建白名单的架构组匹配与默认值。
  - 构建队列过长时截断软件包列表，避免 GitHub 与 Telegram 机器人推送消息超长。

## 三、 系统研发工作深度报告

### 3.1 安同 OS 进展与技术综述

**主讲人：** 白铭骢

- **架构维护现状**：
  - 二级架构依然保持现状，但 RISC-V 取得显著进展。AArch64 关注度较低。

- **重点交付与维护质量**：
  - **核心功能**：去年 11 月交付 Core 13，全组件补丁/脚本整理，核心工具链升级（glibc 2.42, GCC 15）。
  - **KDE 6 适配**：多次测试评审后仍有大量体验相关的已知问题，今年的目标是完成 stable 交付。
  - **质量工作**：全仓库排查将构建失败率从 10% 降至 2%，清理了大量多年未重构的“卫生死角”。
  - **内核维护**：延续 AOSP Kernel Common 补丁规范，后续将引入 Canonical 的 annotations 工具实现配置归一化和声明化（7.0 内核已重新同步基础配置）。
  - **架构兼容**：实现对“非 Debian 架构名”（如 loongarch64 vs. loong64）的兼容，适应商业软件生态。
  
- **上下游合作与影响力**：
  - **Box64**：提供稳定包与 topic 每小时自动更新测试源，安同 4KiB 分页内核获得作者 ptitSeb 推荐，并作为龙架构开发平台。
  - **Mozilla**：贡献者 csmantle 同为官方贡献者，利用 topic 机制测试 Profiler 功能，保障更新质量。
  - **国产硬件**：支持西电 ICPC 校赛；协助格兰菲修复龙架构 4KiB 分页及兼容问题。

### 3.2 质量工程与大重构

**主讲人：** 潘任周

- **全仓库测试与安全维护**：
  - 去年 8 月起筛查出 400 多个构建失败的包，目前已修复超 3/4。
  - 计划年内启动类似 Fedora 的定期全仓库重构。
  - **安全更新**：
    - 年度安全更新发布量达到历史总和五倍。
    - 6 月起实施“每周安全公告”，重大漏洞（如 Copy Fail）即时公告。
    - oss-security 报告内容通常在 12 小时内全量推送。
  - **脚本规范**：
    - `ABSHADOW=0`、`RECONF=0` 等语句必须通过 `FIXME` 注释说明原因。
  - **自 AOSCC 2025 以来的改善情况**：
    - ABTYPE 覆盖 18.35% -> 42.64%；
    - CHKUPDATE 覆盖 94.28% -> 94.64%；
    - TUM 更新 72 -> 446；
    - 单独标记的 Spiral 41 -> 68。
  
- **核心组件大重构项目（Survey）**：
  - **Python**：今年 2 月份成功从 Python 3.10 升级至 3.14（今年最大工程，重构了 1000 多个包）。系统不再预装 Python 2。
  - **libxml2**：为修补长达四年的安全漏洞，从 2.10 升级至 2.15，半年内重构了两百多个软件包，带来 HTML5 分词及多层引用等新特性。
  - **Boost**：1.83 -> 1.91 更新，涉及大量 API 变化及 20 多个新增 patch。
  - **PipeWire**：去年 12 月彻底替换了延迟高、蓝牙支持不全的 PulseAudio，成为默认音频服务。
  - **ICU**：正推进从 74 升级到 78 。
  
- **桌面环境更新**：
  - GNOME 49 与 Cinnamon 6.6 合并更新，清理了大量 GNOME 旧软件。
  - 停止维护 LXDE，LXQt 2 暂于 KDE 6 分支中维护。
  - 引入并持续更新 COSMIC 1.0。

- **编程环境更新**：
  - Go（9 次更新、大量重构）
  - Node.js（全面切换至 26 版本为主力）
  - Deno（每周更新，现至 2.9.3）
  - Perl（5.36 -> 5.42）
  - OCaml（5.4，重构 30 多个包）
  - OpenJDK（默认版本 21 -> 25）
  - .NET（8 -> 10，支持源码构建及几乎所有架构）
  - Haskell GHC（9.4.8 -> 9.14.1，借助 Debian 软件包自举扩展至除 loongson3 外的全部主线架构，为这些架构带来 Pandoc）

### 3.3 Core 14 前瞻

**主讲人：** 席若尧

- **工具链升级**：
  - 默认及系统构建使用的 GCC 由 15.3.0 升级至 16.2.0，glibc 由 2.42 升级至 2.44。
  
- **GCC 调整**：
  - `gcc-runtime` 虚包只提供 GCC 16 的 SONAME，不再提供静态库和无版本共享库。
  - `libcc1.so` 改由 `gcc-16` 提供，避免非默认 GCC 错链 GCC 16 运行库。

- **glibc 清理与优化**：
  - 多数架构改为启用 multi-arch，根据硬件自动使用 LSX、LASX、AVX2 等优化实现。
  - 停用维护欠佳且已有现代替代方案的 nscd。

### 3.4 小熊猫包管理 / oma 进展

**主讲人：** 傅孝元

- **近期工作进展**：
  - **操作体验**：引入可选 Y/N 模式；重构 oma history 与 oma undo 界面。
  - **底层架构**：HTTP 下载逻辑重构，更为标准且性能大幅提升。
  - **amo 引擎**：推出 oma 的 D-Bus server 实现（类似 PackageKit），实现索引缓存，使 TUI、search 及 command-not-found 实现几乎零延时。
  - **功能与生态**：新增 spdlog-rs、镜像源延迟测试工具、Termux 支持、帮助本地化及 TUM 样式更新。
  
- **AI 辅助开发的挑战**：
  - AI 可为新功能和重构带来灵感，但幻觉问题使审阅与测试更关键，也推动维护者更重视代码注释。
  
- **重构方向**：
  - 推进功能对标 `libapt-pkg` 的 `oma-apt-pkg`，但不追求 API 一比一兼容。
  - 基于 resolvo 构建依赖解析器及包管理外围 API，并细分 `oma-fetch`、重新设计其 API。

### 3.5 星霞 OS (Retro) 与架构改进

**主讲人：** 白铭骢、杨欣辉

- **安装盘改进**：
  - 默认镜像切换至 EROFS，amd64 测试安装时间由 380 秒降至 316 秒。
  - 完善 Petitboot、Linuxboot 和 Rufus 兼容性，改用 F4 手动启用串口以规避部分固件死机。
  - 安装选项可预装 nvidia-open、格兰菲、兆芯等显卡驱动。
  - 安全启动提示增加说明链接。
  - 停止提供 LiveKit。
  
- **自举与维护机制**：
  - 3 月开始设计 Kaboom2，7 月发布首个星霞 OS 移植 BuildKit。
  - 将流程统一为“交叉编译最小环境 -> Stage 2 -> 完整 BuildKit -> 完整重构”。
  - 重做 Stage 2 定义，削减可选依赖、拆解依赖环、补充自举流程并清理无效定义，使新架构移植主要聚焦 GCC、LLVM、Mesa 等架构特定软件包。
  - 星霞 OS 与安同 OS 共用源码树并跟随主线更新，启用 64 位 `time_t`、大文件支持和 LTO，同时按必要性削减软件包特性、依赖和体积。
  
- **具体架构进展**：
  - 当月同步推进 ARMv4、m68k 和 Alpha 移植。
  - 计划开展 PowerPC、loongson2f 并继续推进 IA-64。
  - **IA-64 移植**：在 johnny-mnemonic 等人协作下，修复 glibc Bug，完成 Ruby 移植，目前已有机器进入自举第二阶段。
  
- **系统形态规划（三档配置）**：
  - 完整桌面（TDE，目标最低 128MB 内存、3GB 硬盘）。
  - 精简桌面（IceWM）。
  - 最小系统（命令行）。

### 3.6 安可 OS (长毛兔计划) 探讨

**主讲人：** 白铭骢

  - **LTS-G**：对应信创规范，维护 2 年。
  - **LTS-I**：面向国际需求，对齐 Ubuntu 新 LTS 周期（2 年）。

- **上游交互**：
  - 引入 OpenStack、PVE 等服务器软件栈。
  - 分享主线架构移植经验。
  - 探讨对申威架构的支持。

## 四、 社区 AI 政策探讨

**主讲人：** 白铭骢

- **原则性规定**：
  - 出台《安同开源社区 AI 辅助工具使用及披露约定》，定下“允许使用、人类把关、声明来源”的基调，并要求贡献者后续能自主完成 ABBS 树内由 AI 辅助的修改。

- **观察**：
  - AI 大幅降低了功能重构的起步成本，消除重复劳动。
  - AI 增加了代码审查的“心智负担”：
    - 审阅工作变得更加耗时和严苛。
    - 倒逼了代码质量的提升。

### 5.2 星霞 OS 实体安装介质设计与制作

**主讲人：** 刘璨贤

- **外观与结构设计**：
  - 理念：致敬上世纪末、本世纪初软件行业的黄金年代，还原数字时代缺失的“拥有感”和“掌握感”。

- **分发模式**：
  - 对于已购买的使用者，采用“邮购分发”订阅更新机制——通过挂号信寄出新的光盘页和说明书替换件。

- **当前进展**：
  - 活页夹样品已制作完成，正在推进软盘袋与光盘袋等附件的设计，预计年底交付首批成品。

## 六、 闭幕杂谈：外卖不是树上长的

- **社会人的挑战**：
